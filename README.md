# Academic Paper Workflow · 通用学术论文阅读与归档助手

把**选论文、下载正文、阅读提炼、Word 简读和 Zotero 归档**串成一套可重复执行的 Codex 工作流。支持自然科学、医学、计算机、工程材料、经济与社会科学、数学和人文学术论文，帮助研究者持续积累文献并回顾重要发现。

按研究方向筛选相关性高、证据扎实或有方法启发的文章，并根据学科与论文类型调整简读重点：实验研究看设计与证据，计算机论文看数据与基线，实证研究看识别策略，理论论文看假设与证明，综述看证据覆盖范围。

- **有依据地选文**：核对来源、元数据和版本，检查已有文献，减少重复推荐。
- **下载正文 PDF**：优先合法开放全文，默认不下载补充材料；机构全文需已有授权。
- **生成中文简读**：梳理研究问题、方法或论证、主要发现、证据局限和课题启发。
- **整理 Zotero**：归入自定义主题分类，添加标签、结构化笔记和正文附件。
- **统一文献编号**：PDF、Word 和 Zotero 笔记一一对应，方便查找与长期积累。

原土壤研究场景继续支持。为兼容已有安装和仓库链接，技能调用名及仓库名仍为 **soil-paper-workflow**；通用能力通过升级后的说明和学科配置提供。

## 支持的阅读场景

| 场景 | 阅读重点 |
| --- | --- |
| 土壤 生态 环境与自然科学 | 对照与独立重复、机制证据、尺度及适用范围 |
| 医学与生命科学 | 研究设计、终点、效应量、偏倚及临床外推边界 |
| 计算机与人工智能 | 数据集、基线、消融、数据泄漏与复现 |
| 工程与材料 | 制备与测试条件、性能权衡、耐久性与可扩展性 |
| 经济与社会科学 | 数据质量、识别策略、稳健性及解释范围 |
| 数学与理论研究 | 定义、假设、定理、证明结构及边界 |
| 人文与解释性研究 | 材料与语境、概念、论证链及替代解释 |

这些是学术阅读与整理能力，不代表保证每篇论文都可下载，也不替代专业同行评议。[学科阅读说明](references/disciplines.md)给出具体检查点。

## 编号一致

| 交付物 | 示例格式 |
| --- | --- |
| PDF | 日期_文献七_论文名.pdf |
| Word | 日期_文献七_中文主题.docx |
| Zotero 笔记 | 文献七｜要点｜中文主题（期刊 年份） |

PDF 放论文目录的“文献”，Word 放“简读”。编号由已有文献与 Zotero 核对后确定，不会按当天日期重新从一开始。

## 安装与配置

将本仓库下载到 Codex skills 目录下的 soil-paper-workflow 文件夹，确认 SKILL.md 直接位于该文件夹内，重新加载 Codex。Windows 默认位置为用户主目录下 .codex/skills，也可遵循自己的 Codex 配置。

复制 config.example.json 为本地私人配置，填写输出位置、Zotero 分类、discipline 和 research_focus。脚本路径相对于配置文件解析；真实配置不应提交到 GitHub。现有土壤方向配置可以继续使用，升级不会修改其内容。

## 使用示例

> 使用 $soil-paper-workflow，按我的研究方向选一篇高价值学术论文，只下载正文 PDF，沿用已有文献编号，整理 Zotero 笔记和 Word 简读。

也可以直接说明具体学科：

- 选一篇机器学习可解释性的论文，重点讲数据集、对比实验和局限。
- 找一篇材料科学重要研究，比较测试条件、性能权衡与实际应用边界。
- 整理这篇数学论文，讲清定理假设、关键引理和证明思路。
- 沿用土壤方向配置，关注增温与水分变化对碳循环的影响。

先按[操作说明](references/workflow.md)准备经正文核验的论文信息，再调用辅助脚本：

```text
python scripts/workflow.py prepare --config /path/private.json --paper /path/paper.json --pdf /path/fulltext.pdf --work /path/task
python scripts/workflow.py zotero-import --work /path/task
python scripts/workflow.py zotero-import --work /path/task --commit
```

脚本需要 Python 3.10+、python-docx 和 pypdf；Codex 中优先使用内置运行时。Zotero 导入需要桌面版正在运行且支持官方本地 Connector 接口。不同版本先预览，无法适配时使用已授权的界面工具。

Codex 负责文献筛选、来源核验与阅读，辅助脚本处理确定性的文件与导入操作。Word 生成后还需渲染检查；Zotero 导入后需通过界面或官方只读 API 核实。

每日定时阅读可配合用户设置的自动化；安装技能不会自行创建定时任务。
